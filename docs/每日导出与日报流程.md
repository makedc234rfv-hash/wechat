# 每日导出与日报流程

给执行导出和写日报的 AI / 人看的固定流程。路径用占位符，按本机实际填写。

## 前提

- 台式机微信正在运行，并登录了要导出的那个账号（工具从运行中的微信取密钥）。
- 微信退出期间收到的消息，电脑本地没有；要先在手机：我 → 设置 → 通用 → 聊天记录迁移与备份 → 迁移 → 迁移到电脑，再导出。
- 数据目录可能不在默认位置（例如在其他盘的 `xwechat_files`），以微信设置里“文件管理”显示的为准，用 `--data-root` / `--account` 指定。

## 首次部署检查（只做一次）

1. 校验文件完整性（便携包用 `packaging\校验文件.ps1`）。
2. `--self-test`：11 项通过。
3. `--list-accounts`：多个账号时由本人确认用哪个，之后固定用 `--account`。
4. 先导出一天或一个会话，回读 JSONL 验证条数和内容，再正式使用。

## 每天

1. 导出当天：`--date <YYYY-MM-DD> --account <账号目录> --output <输出根>\<日期>-run1`。重跑用 run2、run3，不覆盖。
2. 需要只看某几个群时先 `--list-conversations` 拿准确会话 ID，再用 `--conversation` 指定（可重复）。
3. 读 `聊天归档\<会话>\<日期>\messages.jsonl`，按会话名判断是否工作相关；名称看不出性质的联系人和无名群也要看完，图片、附件也要看，不留大缺口。
4. 写 `<输出根>\<日期>-runN-工作摘要.md`：进展、未决问题、明日事项。

## 日报规则

- 只写工作内容；不写私人聊天、密码、令牌、截图里的敏感信息、身份证等。
- 不要“风险”段。
- 区分：方案准备 / 脚本离线测试 / 实际执行 / 验收通过。口头判断不当现场验证；旧日期的工作不算当天成果。
- 事实要准，只写聊天里确认过的（例如“确认了线路型号和长度”不能写成“已接线”）。
- 语音未转写、媒体缺失、某天消息没同步过来时，如实注明资料范围。
- 不自动发送日报，除非本人明确要求。
